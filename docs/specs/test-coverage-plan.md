# Test Coverage Plan

## Problem
Overall coverage sits at 33% (`npm run coverage`, v8 provider). The gaps aren't
evenly distributed — they cluster in the highest-risk code: every Server
Action that touches auth or writes data is at 0%. A broken modal looks wrong
on screen; a broken auth or ownership check leaks or corrupts data silently.
Coverage needs to be closed in risk order, not file-alphabetical order.

## Goal
Work toward 100% line/branch coverage, closed incrementally, tier by tier.
This is a portfolio project as well as a prototype — there's no code here
that's "too throwaway to test," and agents make the marginal cost of closing
a gap low enough that leaving it open isn't a time tradeoff anymore. Coverage
should only ever move up: each tier closed becomes a floor the CI threshold
enforces (see **Enforcement** below), so a future change can't silently drop
a file back to 0%.

## Priority Tiers
Ordered by risk × blast radius — a bug here either leaks/corrupts data or
silently breaks the app for every user, vs. a bug in a leaf component that's
visibly wrong and low-stakes.

## Excluded from Coverage
- `lib/supabase/**` — thin client-factory wrappers around the Supabase SDK,
  no branching logic of our own to verify
- `lib/database.types.ts` — generated by `supabase gen types`, not
  hand-written
- `**/layout.tsx`, `**/*.d.ts` — framework boilerplate / type-only files

## Enforcement
Add a coverage floor to `vitest.config.ts` (`test.coverage.thresholds`) so
`npm run coverage` fails if coverage drops below the current baseline. Raise
the threshold each time a tier closes — never lower it. This turns "coverage
should trend toward 100%" into something CI actually checks instead of a
goal that quietly erodes.

## Not Doing
- Testing generated or third-party code (Supabase types, `node_modules`)
- Blocking `npm test` (plain, no `--coverage`) on thresholds — only the
  explicit `npm run coverage` run enforces the floor, so day-to-day
  `npm test` stays fast
- Retrofitting 100% onto every file in one PR — tiers are meant to land as
  separate, reviewable slices
